How skill evidence is collected

Our own scoring is pending (M4).

This page describes the public data behind the skill pages and the scoring plan. The words here are ours. Third-party sites are named so a figure can be traced, and their sentences are quoted on the skill pages rather than rewritten here.

What was collected

A collector in this repository reads public web pages and the GitHub REST API, then writes the JSON file the pages are generated from. It does not log into a site and it does not call a model API. Every stored value keeps the URL it came from and the UTC time of the fetch. When a value could not be read, the file stores a reason, and the skill page repeats that reason.

The set is 20 skills in three jobs. The author's words on a skill page are the description field from that skill's SKILL.md, quoted beside the third-party figures.

Install counts come from the public skills.sh page for that skill. The skills.sh detail API returned HTTP 401 when called without a credential, so the collector left it unused. Audit rows for Gen, Snyk, and Socket come from the public skills.sh audit API. GitHub stars are the star count of the repository that holds the skill. The last commit is the newest commit that touched the skill folder, and the page links to that commit.

The data snapshot for these pages is 2026-11-01 14:39:05 UTC.

What each evidence label means

Measured by us. We have run the skill on our tasks and stored the trials. No skill has this label yet, because our own scoring is pending (M4).

Measured by a third party. At least one skill-level effect metric from another project has a value. The metrics that count are SkillzBench pass-rate lift, SkillzBench quality lift, Tessl impact, Driftproof with-skill and without-skill means, Happycapy overall score, Edge mean judge score on a named task (with the skill and without it), Edge wins, ties, and losses, and OpenSkillEval average score.

Popular but unmeasured. Public signals such as installs or stars are on the page, and none of those effect metrics has a value.

Tessl quality, SkillzBench trust, and SkillzBench quality judgment are not counted as measurements. They stay on the skill page when the source published them, and they do not set the evidence label. The same exclusion covers Edge baseline outputs passed, recorded agent runs, skill outputs passed, and a SWE-Skills-Bench note that a name is listed in a table. A table listing is not a score. The SWE-Skills-Bench repository URL named in its paper returned HTTP 404, so the collector read the public paper table and stored no numeric SWE result.

A result published for a pack, a plugin bundle, or a whole repository is not copied onto one skill inside it. When that is the only entry a source has, the skill page says the per-skill value is unavailable and gives the reason.

Three arms, once scoring starts

The planned comparison has three arms: no skill, the skill, and a length-matched placebo. The placebo is text of the same length as the skill, without the skill's instructions. Each arm is planned for repeated trials. A published score will include pass-rate lift, a confidence interval, tokens, and cost. Every score will name the model that produced it.

The run record will name the model, the harness version, the skill commit, the task version, the seeds, the verifier, the pass or fail of each trial, the token cost, and the command that reruns it. Any cut to tasks or trials will be written into that record. Until a record exists, job pages stay in alphabetical order by slug.

Run records will live under /skills/runs/. None are recorded yet.
